## 1. 引言

### 1.1 目的

定义「社交页排序 mod」的功能与非功能需求，作为概要设计、详细设计、测试用例的唯一依据。凡本文件未列出的功能，不进入 v1。

### 1.2 范围

本 mod 在星露谷 1.6 的原版社交页上加一个排序入口，让玩家按好感、名字（拼音）、生日重排 NPC 条目，并记住上次选择。

不涉及：游戏数据处理、存档写入、联机同步、原版界面重做。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 社交页 | `GameMenu` 中的社交标签，`StardewValley.Menus.SocialPage` |
| 条目 | 社交页中的一行角色，`SocialPage.SocialEntry` |
| 玩家段 | 列表最前 `numFarmers` 个条目，联机时为其他玩家 |
| 显示名 | `SocialEntry.DisplayName`，本地化后玩家看到的名字 |
| 内部名 | `SocialEntry.InternalName`，NPC 内部名或玩家联机 ID，稳定不变 |
| 原顺序 | 游戏自己生成条目列表时的顺序 |

### 2.1 运行环境

| 项 | 值 |
|---|---|
| 游戏 | Stardew Valley 1.6.15.24356（Steam） |
| 框架 | .NET 6.0.32 |
| 加载器 | SMAPI 4.5.2 |
| 补丁库 | Harmony（随 SMAPI 自带） |
| 目标框架 | net6.0 |

### 2.2 用户特征

中文玩家为主，使用大量内容扩展 mod（SVE、Ridgeside、East Scarp 等），社交页条目可达数百，需要按不同标准快速定位角色。

### 2.3 前置依赖

必需：SMAPI。用户不需要单独安装 Harmony。

可选：Generic Mod Config Menu。未安装时全部功能仍然可用，只是没有游戏内设置界面。

### 2.4 约束

- 不修改游戏原版的数据与逻辑，只调整社交页的显示顺序
- 不写存档，卸载 mod 后存档不受影响
- 不改变玩家段的位置与数量

## 3. 功能需求

### FR-1 排序入口

FR-1.1 社交页打开时，在标签条最左侧的空白格显示一个排序按钮，不遮挡标签、滚动条、关闭按钮与其他原版控件。该格在 1.6 原版中始终为空（第一个标签的 bounds 从 `x+64` 开始）。不使用右上角，因为 UI Info Suite 2 等 mod 会在那里自绘按钮，且这些按钮不在 `GameMenu.tabs` 中，无法可靠枚举避让。

FR-1.2 点击按钮展开排序面板，面板竖向列出三个排序项，每项右侧显示方向箭头。

FR-1.3 面板打开时，点击面板以外的区域关闭面板，不改变当前排序。

FR-1.4 菜单关闭或切换到其他标签时，面板状态重置。

FR-1.5 ESC 在 v1 不拦截，行为与是否打开面板无关（关闭整个菜单）。

### FR-2 排序方式

FR-2.1 好感排序

主键为心的等级，按配置方向排列；同级时按精确好感点数排列，方向与主键一致；仍相同则按 FR-2.2 的名字比较规则升序。无法读取好感数据的条目排在有数据条目之后。

FR-2.2 名字排序

主键为显示名，方向可切换。名字分两段比较：

- 汉字段：以汉字开头的名字，按 zh-CN 拼音顺序比较。
- 非汉字段：其余名字（拉丁字母、数字、其他文字等），按字母顺序比较。

非汉字段整体排在汉字段之后，该分段顺序不受升降序影响（降序只翻转段内顺序）。两段的所有比较统一忽略大小写、全半角与变音符号，避免仅显示差异导致顺序抖动。比较结果仍相同时，按 `InternalName` 序数升序兜底；再相同则保持原相对顺序。

FR-2.3 生日排序

主键为「距离下一个生日的天数」，按配置方向排列。当天生日计 0 天。无生日数据的条目排在末尾，保持相对顺序。同一天生日的多人按 FR-2.2 的名字比较规则升序。

FR-2.4 （v1.1 作废）恢复原顺序

原 v1.0 曾要求提供「默认」项以恢复游戏本次打开页面时的原始顺序。玩家确认不再需要该入口，本项及其相关验收标准、决策一并作废。

FR-2.5 玩家段

以上所有排序一律只作用于玩家段之后的 NPC 条目，玩家段位置固定不变。

FR-2.6 未见面角色

`IsMet == false` 的条目在三种排序下都排在有数据的条目之后，彼此之间保持原有相对顺序。

### FR-3 方向切换

FR-3.1 点击排序项的名称，应用该排序并使用该方式的默认方向；默认方向为：好感降序、名字升序、生日升序。

FR-3.2 点击排序项右侧的箭头，仅翻转该方式的方向并立即应用，不关闭面板。

FR-3.3 每种排序方式各自记住方向，切换到另一种方式再切回来，方向保持上次选择。

### FR-4 状态与持久化

FR-4.1 当前排序方式与各方式的方向写入 `config.json`，下次启动沿用。

FR-4.2 首次启动、`config.json` 缺失或读取失败（含 JSON 损坏、字段非法）时，排序方式一律为「好感降序」；三种方向各自取默认值（好感降序、名字升序、生日升序）。读取失败写 warning 日志，不阻断启动。

FR-4.3 配置只在玩家点击选择时写入，不逐帧写入。

### FR-5 可选设置界面

FR-5.1 检测到 GMCM 时注册设置项，可查看和修改排序方式与方向。

FR-5.2 未检测到时跳过注册，不产生错误日志。

### FR-6 兼容

FR-6.1 与其他读写社交页的 mod 共存（UIInfoSuite2、LookupAnything、NPCMapLocations 等），不导致报错或界面错乱。

FR-6.2 支持内容扩展 mod 追加的大量自定义 NPC；生日、好感数据缺失时按 FR-2 的异常规则处理。

## 4. 非功能需求

NFR-1 健壮性：任何排序或绘制异常都必须被捕获，回退到游戏原顺序并记录 warning，不允许使游戏崩溃或菜单失效。

NFR-2 性能：一次排序耗时可忽略，打开社交页无可感知延迟；不对每帧绘制做排序。

NFR-3 可维护性：所有对游戏内部成员的访问集中在单一访问层，游戏版本变动时只修改该层。

NFR-4 可卸载性：删除 mod 文件夹后游戏恢复原状，无残留依赖。

NFR-5 本地化：所有玩家可见文本走 i18n，至少提供简体中文与英文。

NFR-6 侵入性：只使用前缀/后缀补丁，不替换游戏方法。

---

## 5. 边界与非目标

不做：

- 手动拖拽排序
- 排序结果的实时刷新（送礼改变好感后不立即重排，下次打开生效）
- 自定义排序规则、组合排序
- 修改好友度、数值、存档
- 修改社交页外观（除按钮与面板外）
- 恢复原顺序（回到游戏自己生成的顺序；该入口已在 v1.1 删除）

## 7. 待验证项

| 编号 | 内容 | 影响 | 验证方式 | 结论 |
|---|---|---|---|---|
| TBD-1 | `SocialPage` 相关字段的可访问性 | 是否需要反射 | 编译验证 | 已确认：`SocialEntries`、`sprites`、`characterSlots`、`numFarmers`、`slotPosition`、`scrollBar`、`scrollBarRunner`、`upButton`、`downButton` 均为 public；`SocialEntry` 为 public 嵌套类型，字段 public。实现不使用反射。 |
| TBD-2 | 构造期 `FindSocialCharacters` 与 `CreateComponents` 的先后 | 补丁点选取 | 打日志观察 | 已确认（1.6.15 程序集 IL + 游戏内日志）：`SocialEntries = FindSocialCharacters()` → 计算 `numFarmers` → `CreateComponents()` → 定位 `slotPosition` → `setScrollBarToCurrentIndex()` → `updateSlots()`。游戏日志中每次打开菜单均先出现 `FindSocialCharacters`、后出现 `CreateComponents`（例：16:43:17 #1 → #2）。 |
| TBD-3 | 游戏进程内 ICU 对汉字是否按拼音排序 | 是否需内置拼音表 | 一次性测试 mod | 已确认：游戏进程日志输出 `culture=zh-CN, compareInfo=zh-CN`，样例「阿比盖尔<山姆=True、德米特里厄斯<法师=True」。名字升序实测：阿比盖尔、阿黛莱德、阿圭尔先生、阿莉雅、艾登、艾芙琳、艾利欧特、艾莉莎、艾琳、艾米丽；名字降序实测：Aliyah、朱丽叶、直美、约瑟芬、佑马。无需内置拼音表。注：v1.2 起改为显式分段，非汉字段固定排在汉字段之后（不再依赖 ICU 的隐式顺序），段内比较忽略大小写/全半角/变音符号。 |
| TBD-4 | 原版社交页顺序是否等于好感降序 | 默认排序语义 | 反编译 + 游戏日志 | 已确认：原版顺序为「玩家段 + 已见面 NPC（`Friendship.Points` 降序 → 见面顺序 `OrderMet` → 显示名）+ 未见面 NPC（按名）+ 孩子（按名）」。实测存档 132 条（已见面 129、未见面 3），原版前 10 名为艾米丽(2181)→安雅(1806)→潘姆(1541)→格斯(1409)→莱妮(1324)→比尔(1247)→克莱尔(945)→迈克尔(941)→金珀(895)→潘妮(884)，按「心等级→点数」检查结果为 True。结论：主键相同，但同分时原版按见面顺序而非拼音，未见面/孩子单独排末尾，因此不等于本需求的「好感降序」，不能默认等同。 |

> 说明：TBD-1~TBD-4 均已通过编译、反编译与游戏内日志/截图确认。按钮定位经过两次修正：v1.1 的固定右上角会与关闭按钮/标签重叠；v1.2 的「最后一个标签右边界」动态定位仍与 UI Info Suite 2 自绘的锤子按钮重叠（该按钮不在 `GameMenu.tabs` 中，无法枚举）。v1.3 改为标签条最左侧空白格。截图 09 像素核对：菜单左边 x≈57、第一个标签 `bounds.Left`=121、标签贴图最左可见像素≈105；新按钮范围 x≈61..99，与标签贴图至少留 6px；实机截图 10 确认按钮位于标签条最左格、无遮挡。当前排序项仍以左侧深色竖条 + 浅黄底色标记。

## 8. 决策记录

| 编号 | 决策 | 理由 |
|---|---|---|
| D-1 | 只做排序，不做拖拽 | 拖拽工作量约为排序的三倍，且输入拦截最易反复 |
| D-2 | （v1.1 作废）默认方式为游戏原顺序 | v1.1 删除「恢复原顺序」入口，默认方式改为好感降序（见 FR-4.2） |
| D-3 | 玩家段不参与排序 | 联机玩家无生日与好感，混排会打乱游戏对玩家段的分段处理 |
| D-4 | 未见面角色排末尾 | 信息量为零，前移无意义 |
| D-5 | 方向以箭头切换，默认方向固定 | 面板保持三项，交互可发现 |
| D-6 | 方向按方式分别记忆 | 切换方式后不丢失选择 |
| D-7 | 不实时重排 | 避免送礼时条目在鼠标下跳走导致误点 |
| D-8 | ESC 不拦截 | 需在 GameMenu 层打补丁，成本高于收益 |
| D-9 | GMCM 为软依赖 | 不增加必需的安装步骤 |
| D-10 | 生日不硬编码季长与年长 | 使用游戏日历换算，适应版本变化 |
| D-11 | 名字排序分段：汉字段拼音在前，非汉字段字母序在后；比较忽略大小写/全半角/变音符号，`InternalName` 兜底 | 避免中英混排时拉丁名位置突兀；避免仅大小写或全半角差异导致顺序抖动与多次打开不一致 |
| D-12 | 排序按钮固定在标签条最左侧空白格，而非右上角 | 右上角会被 UI Info Suite 2 等 mod 自绘按钮占用（不在 `GameMenu.tabs` 中，无法枚举避让）；左侧空白格是 1.6 原版唯一稳定可用的位置 |
